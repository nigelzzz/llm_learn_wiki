# 鏈表（Linked List）學習 Context Pack

## Big Picture

鏈表是「以指標串接的線性結構」，與陣列相對：
- **陣列**：連續記憶體 → 隨機存取 O(1)，但插入/刪除需要搬移。
- **鏈表**：節點靠指標連接 → 任意位置插入/刪除是 O(1)（只要拿到前驅節點），但隨機存取需 O(n)。

鏈表問題的本質只有兩件事：
1. **指標的重接**（rewire）：誰指向誰？
2. **不變式（invariant）的維持**：在每一步修改前後，鏈表結構必須仍然合法（不能斷鏈、不能成環、不能讀到野指標）。

這份 context pack 圍繞灵茶山艾府的鏈表題單，從第一原理拆解 11 個子題型（§1.1 ~ §1.11），把所有題目都歸納到「同一套手法」之下。

## Why It Matters

- **面試核心**：鏈表是 Google / Meta / 字節 等公司白板題的常客，考的是「指標思維」與「邊界處理」。
- **工程基礎**：LRU、LFU、跳表、雙向鏈表 → 直接出現在系統設計（緩存、調度器、Linux kernel `list_head`）。
- **資料結構心法**：鏈表訓練出的「dummy node」、「快慢指針」、「前後指針」三種思維模式，會在樹、圖、滑窗中反覆出現。
- **與你背景的銜接**：你寫 C++ / 系統程式，已熟悉指標。鏈表題的價值是訓練「修改指標時保持資料結構不變式」這種思維 — 對 CUDA kernel、KV cache 管理（page-attention）、free-list allocator 都是同一套思路。

## 帶著兩個問題學

整份題單最終要回答兩個問題（這也是 §1 第一頁就提出來的）：

### Q1：什麼情況下要用 dummy node（哨兵節點）？

**第一原理**：dummy node 解決「頭節點本身可能被刪除/修改」的不對稱問題。

當你需要操作的「目標節點」可能就是 head 時，沒有 dummy 就要寫一段「if 是 head 怎麼辦 / else 怎麼辦」的特例。dummy 讓 head 也擁有「前驅節點」，於是所有節點處理都統一成同一段程式碼。

**判斷規則**：
- 會「刪除節點」且 head 可能被刪 → 用 dummy。例：203、19、82、83 (推薦)、237。
- 會「插入節點」且可能插在 head 前 → 用 dummy。例：147、2807、合併鏈表類。
- 「合併 / 構造新鏈表」→ 幾乎一定用 dummy。例：21、2、23、148、1669。
- 只是純「遍歷不修改結構」→ 不需要 dummy。例：1290、141、234（讀取階段）。

### Q2：迴圈條件 `while (node != null)` vs `while (node.next != null)`？

**第一原理**：問你「想停在哪裡」。

| 寫法 | 停止位置 | 適用場景 |
|---|---|---|
| `while (node != null)` | 走到 null 才停（走完所有節點） | 需要存取「當前節點本身的值」，例如累加、計數、複製 |
| `while (node.next != null)` | 停在最後一個節點 | 需要存取「下一個節點」，例如刪除/插入 next、找尾部、相鄰兩兩比較 |

簡記：**要不要看 `node.next`？要看 → 必須保證 next 存在 → 用 `node.next != null`。**

快慢指針還會多一條：`while (fast != null && fast.next != null)` — 因為要同時跳兩步，兩個位置都不能是 null。

## 三大思維模式

整個鏈表題單可以濃縮成三個「指標模板」：

1. **Dummy + Prev 雙游標**：刪除/插入/合併。`dummy → ... → prev → cur → ...`，永遠操作 `prev.next`。
2. **快慢指針**（Floyd）：找中點、判環、找環入口、找倒數第 K 個。差距用「快指針步數 = 2 × 慢指針步數」或「快慢起點差 K」。
3. **三指針反轉**：`prev / cur / next`，每步做 `cur.next = prev; prev = cur; cur = next`。

題單的所有題目都在組合這三個模板 + 邊界處理。
