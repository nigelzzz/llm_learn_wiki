# 鏈表常見誤區（Confusion Log）

> 這份檔案是「初版預警」。每天練完題請追加：日期、題號、卡的點、根因、新理解。

## 通用誤區（七大坑）

### 坑 1：忘了暫存 next 就改 cur.next
**症狀**：反轉後鏈表變短、自迴圈、或丟失後段。  
**根因**：`cur.next = prev` 之後，原本的 `cur.next` 已經不可達。  
**解法**：永遠先 `nxt = cur.next` 再改寫。  
**口訣**：「先存後改」。

### 坑 2：在 dummy 思路下，把 prev 與 cur 混淆
**症狀**：刪錯節點 / 多刪 / 少刪。  
**根因**：dummy + prev 模板裡，要刪的是 `prev.next`，前進是 `prev = prev.next`，但刪了之後 `prev` 不能前進（新的 `prev.next` 還沒判斷）。  
**解法**：寫成 if-else 兩個分支，不要把 advance 與 delete 混在一起。

### 坑 3：迴圈條件錯配
**症狀**：NullPointerException / 走過頭。  
**範例**：找中點寫成 `while fast.next.next` 沒先判 fast.next → 鏈長 = 1 時 NPE。  
**解法**：嚴格遵守「要存取的最深成員必須非 null」。

### 坑 4：頭節點被改了卻回傳原 head
**症狀**：返回的鏈表少了第一段，或返回了被刪除的頭。  
**根因**：head 已不是新的鏈表起點。  
**解法**：能 dummy 就 dummy，最後 `return dummy.next`，永遠不要相信原 head 還是頭。

### 坑 5：合併鏈表後忘記接尾
**症狀**：合併到一半，剩下那條鏈表沒接上。  
**解法**：迴圈結束加上 `tail.next = a or b`。

### 坑 6：環形鏈表沒斷尾
**症狀**：把鏈表斷成兩段時忘記把前段尾部 `next = null`，造成新前段仍指向後段，輸出無限長。  
**範例**：148 排序鏈表用快慢指針切兩半，必須 `prev = slow's prev; prev.next = null`。  
**解法**：「切」鏈表時想清楚誰是前段尾節點，明確設成 null。

### 坑 7：雙向鏈表 detach 忘了動 prev
**症狀**：刪了節點後，下一個節點的 prev 還指向被刪的節點。  
**解法**：detach 永遠寫成 `node.prev.next = node.next; node.next.prev = node.prev`。配 dummy head/tail 可省去 null 判斷。

## 模板專屬誤區

### 反轉（§1.4）
- 區間反轉（92）忘記把「反轉段的尾」接回後續鏈 → 鏈表斷裂。
- 25 題 K 不夠時的處理：**保留原樣**而不是反轉剩下的（注意題目要求）。

### 快慢指針（§1.6）
- 偶數長度的中點到底要哪一個？面試先確認題意。
- 234 回文題：找中點後反轉「後半」要從 `slow` 還是 `slow.next` 開始？標準寫法是反轉 `slow.next` 之後（slow 自己當斷點）。

### 倒數第 K（§1.5）
- `for _ in range(k)` 走 k 步 vs k+1 步：用 dummy 起點時走 k 步即可，slow 最後停在「目標前驅」。
- 邊界：k = 鏈長時，要刪的就是 head；用 dummy 才能統一處理。

### 合併（§1.8）
- 2 題的個位在 head：直接同步加 carry，**不要先反轉**。
- 445 題的高位在 head：才需要反轉或 stack。
- 別把這兩題的方向搞反。

### LRU（§1.10）
- HashMap 必須存 `key → node`，不能存 `key → val`。
- evict 時要 `del map[lru.key]`，否則 HashMap 會 leak。
- node 用 `__slots__` 可省記憶體（面試加分）。
