# 面試題與口頭回答

## A. 概念題（口頭回答，10 題）

### 1. 鏈表 vs 陣列，何時用哪個？
- 隨機存取多 / 固定大小 / cache 友善 → 陣列。
- 頻繁中段插入刪除 / 大小變動劇烈 / 需要在 O(1) 內 splice → 鏈表。
- 注意：現代 CPU 上「線性掃描鏈表」遠慢於「線性掃描陣列」（cache miss）。

### 2. 什麼時候要用 dummy node？
**回答模板**：當 head 自己可能成為被刪除/插入/修改的對象時，dummy 提供統一的「前驅」，避免特例判斷。
具體：
- 刪除節點且 head 可能被刪（203、82、19）。
- 構造新鏈表（21、2、23、合併類）。
- 區間反轉而 head 在區間內（92、25）。
- 要持續維護「prev / tail」游標時。

### 3. `while (node != null)` 與 `while (node.next != null)` 的差別？
取決於迴圈體裡要存取什麼。要看 `node.val` → `node` 必須非 null；要看 / 改 `node.next` → `node.next` 必須存在。
快慢指針合用：`while (fast != null && fast.next != null)`，因為要 `fast.next.next`。

### 4. 解釋 Floyd 判環演算法為何能找到入口。
（白板畫圖）設 head 到入口 a，入口到相遇點 b，環長 L。  
`slow = a + b`，`fast = 2(a + b) = a + b + nL` → `a + b = nL` → `a = (n-1)L + (L - b)`。  
所以「從 head 走 a 步」等於「從相遇點再走 a 步」會在入口相遇。

### 5. 如何 O(1) 空間判斷迴文鏈表？
找中點 → 反轉後半 → 雙指針從兩端比對。比完可選是否還原（看面試官要求）。

### 6. 反轉鏈表的迭代版需要幾個指標？為什麼？
三個：`prev / cur / next`。在改 `cur.next = prev` 之前必須先暫存 `next = cur.next`，否則丟失後續鏈。

### 7. 如何 O(1) 刪除單向鏈表中給定的節點（不給 head）？
覆蓋值法：`node.val = node.next.val; node.next = node.next.next`。前提：node 不是尾節點。

### 8. LRU 為何用「HashMap + 雙向鏈表」？
- HashMap 提供 O(1) 查找節點。
- 雙向鏈表提供 O(1) 從中間 detach + 重新插入頭部。
- 必須是雙向，因為 detach 時要拿到前驅；單向只能 O(n) 找前驅。

### 9. K 個一組翻轉鏈表，邊界如何處理？
維護 `group_prev`，每輪從 `group_prev.next` 開始往前走 K 步：
- 走不到 K 個 → 直接結束（這組保留原樣）。
- 走到 K 個 → 反轉這 K 個並把 `group_prev.next` 重新指向新頭，把原本的舊頭設成新的 `group_prev`。

### 10. 如何在鏈表上實作 mergesort 達 O(1) 額外空間？
自底向上：先按 size = 1, 2, 4, ... 倍增，每輪掃整條鏈，每兩段做 merge，用 dummy 串起新鏈。避免遞迴堆疊。

## C. 口頭追問（Follow-ups）

面試官常見追問：

### 「如果鏈表很長，記憶體限制嚴格，怎麼辦？」
- 優先 O(1) 空間解。
- 反轉、mergesort、找中點都有 O(1) 空間版。
- 避免用遞迴（會產生 O(n) call stack）。

### 「如果是雙向鏈表呢？」
- 刪除節點直接 O(1)，不需要 prev 變數。
- 反轉就是把每個節點的 prev/next 互換。
- 找中點仍然用快慢；判環一樣可用 Floyd。

### 「如果鏈表有 cycle，你的演算法會無限迴圈嗎？」
- 多數題目可先判環再處理。
- 反轉、合併、找長度等若沒先判環，會無限走 → 必須假設無環，或先做判斷。

### 「能不能用 stack / queue 解？」
- 兩數相加 II（445）：用兩個 stack 比反轉容易。
- 234 回文：把值丟 stack 比一遍。但這通常違反「O(1) 空間」要求，要主動提出 trade-off。

### 「如果 LRU 要 thread-safe？」
- 簡單做法：整個 get/put 加鎖。
- 進階：分桶（concurrent HashMap），但雙向鏈表的 splice 仍需臨界區。

## D. 解題前的「30 秒分類」

看到鏈表題，先在腦中問自己：
1. 涉不涉及「結構修改」？  
   - 是 → 99% 用 dummy。
   - 否（純讀）→ 直接 cur 走到底。
2. 是否需要「相對位置」？  
   - 倒數第 K → 錯位指針。
   - 中點 → 快慢指針。
   - 環 → 快慢指針。
3. 是否在「合併 / 分流」？  
   - 對 → dummy + tail 模板。
4. 是否要「O(1) 操作」？  
   - 對 → 雙向鏈表 + HashMap。

回答出這 4 個問題，模板自然浮現。
